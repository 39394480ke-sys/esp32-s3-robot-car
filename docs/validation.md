# 硬件验证状态

本页只保留实物和电气层面的验证结论，不记录固件模式、算法参数或软件调试过程。状态代表这套硬件曾经达到过的结果，拆装或重新接线后仍需复测。

## 必须保留的风险记录

### TOF 视窗遮挡

装壳后 TOF 曾从可变化的读数回到持续近距离或 0 值。最可能的硬件原因是外壳边缘、线束或近距离结构进入视场。重新装配时应在合壳前后分别测量，并移动遮挡物确认变化。

### 摄像头 FPC 与温升

历史拆装中曾出现摄像头或转接区域异常发热并立即断电的情况。每次连接 OV3660 前必须确认：

- 型号与开发板摄像头座匹配
- 金手指方向正确，FPC 插到底并锁紧
- 3V3/GND 没有接反或短路
- 排线没有破损、死折或被外壳压住

首次复测应短时间上电并监测温度，异常发热立即断电。

### 原型线束可靠性

当前内部照片使用面包板、杜邦线和胶带连接，适合桌面验证，不适合长期振动。重新开发时应把以下项目作为硬件升级重点：

- 电机、舵机和电池使用有锁连接器及合适线径
- 电源入口增加保险或过流保护
- 关键线束做应力释放和两端标签
- 逻辑线与电机动力线分束
- 电路板使用隔离柱或可靠支架固定

### TB6612 模块差异

历史问题包括控制线遗漏和模块方向理解错误。不同 TB6612 小板的排针次序可能不一致，必须以实物丝印为准，并分别测量 `VM`、`VCC`、`STBY` 与 GND。

### 编码器方向

两侧编码器信号都已验证存在，但右侧计数方向曾与左侧符号相反。这不代表编码器损坏；重新开发时需要统一机械前进方向、`M+/M-` 极性和 `H1/H2` 相位定义。

### 编码器 GPIO 与 Octal PSRAM

当前整机把编码器连接到 GPIO35、GPIO36、GPIO37 和 GPIO43，其中
GPIO35、GPIO36、GPIO37 属于当前 ESP32-S3 的 Octal PSRAM 总线。当前接线
状态下，Camera Benchmark 和 Camera Streaming 固件都在 PSRAM 初始化阶段
失败并重启。

这是已经观察到的资源冲突和启动现象，但尚未通过断开 GPIO35、GPIO36、
GPIO37 外部连接的 A/B 测试证明直接因果关系。后续使用 PSRAM 前应先完成
断线 A/B 验证，并重新分配编码器 GPIO 或调整整车控制架构。

## 重新接线后的最小复测顺序

1. 断电检查 12V 正极与 GND 是否短路。
2. 断开负载，分别测量 LM2596-A 约 6V、LM2596-B 约 5V。
3. 接入 ESP32-S3，确认 5V 输入、3V3 输出和板载温度正常。
4. 检查 OLED、MPU6050、TOF、INMP441、TTS 和 OV3660 的供电及基本响应。
5. 确认两个 SG90 的中位、行程和线束余量。
6. 架空车轮，分别确认左右电机方向和编码器信号。
7. 合壳后再次确认 TOF 视场、OV3660 画面、OLED 可视性和所有机械间隙。
